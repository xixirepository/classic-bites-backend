# 대학 목차·본문 등록

사용자의 2026-09-30 요청에 따라 기존 사서오경 → 대학 아래에 경 1장·전 10장과 원문·한국어 번역·해설 34개 한입을 준비했다. 앱이 기존 공개 API로 조회하는 콘텐츠이며 앱 코드나 API 계약을 변경하지 않는다.

## 판본과 편집 범위

- 원문: 주희 『사서장구집주』의 [『대학장구』 고정판](https://zh.wikisource.org/w/index.php?title=四書章句集註/大學章句&oldid=2647788), 위키문헌 판 ID `2647788`.
- 저작권이 만료된 고전 원문을 사용했다. 서문·일반 장구 주석·장 끝 해제는 제외하고 경전 본문과 전 5장의 주희 격물치지 보전을 실었다. 현대 번역문을 전재하지 않았다.
- 전 5장의 잔존 문장과 주희 보전은 별도 한입으로 나누고 제목·해설·데이터의 `text_type`에서 구분한다. 보전을 고대 경전 원문으로 설명하지 않는다.
- 한국어 번역·해설과 한입 소제목은 이번 작업에서 새로 작성했다. 학습용 초안이며 전문 감수 전이다. 각 장의 첫 한입 해설에도 판본·번역 상태·출처를 표시한다.
- `親民`·`身有所忿懥`·`自謙`·`命也` 등은 원문을 유지하고 주희의 풀이와 교정 이견을 해설에서 설명한다. 전 3장의 `賢其賢而親其親` 해석에는 [『주자어류』 권16](https://zh.wikisource.org/zh-hant/朱子語類/016)도 참고했다.
- 문장 순서는 원문과 동일하며 한입 구분을 제거했을 때 각 장의 원문이 추출 자료와 일치함을 대조했다. 최종 출시 판본·전문 감수 절차를 확정한 것은 아니다.

## 등록 도구

[`api/content/daehak.json`](../api/content/daehak.json)에 판본·출처·목차·본문을 보관한다. [`api/import_daehak.py`](../api/import_daehak.py)는 검토한 이 파일을 명시적으로 등록한다. 기존 `migrate_catalog.py --seed-classics`와 서버 설치 스크립트는 여전히 제목만 준비하며 본문을 자동 등록하지 않는다.

등록 도구는 기본적으로 쓰지 않고 계획만 확인한다. `--apply`를 붙이면 11장과 전체 한입을 하나의 트랜잭션으로 공개 등록한다. UUID는 기존 seed namespace와 장·한입의 고정 key로 생성한다. 작품명이 같다는 이유만으로 임의의 다른 작품을 선택하지 않는다.

기존 사서오경·대학의 ID·연결·제목·공개 상태를 잠금 조회하며 부모 정보는 수정하지 않는다. 목차가 비어 있을 때만 추가한다. 이미 같은 내용 전체가 등록되었으면 `unchanged`, 일부만 있거나 제목·순서·본문·공개 상태가 다르면 변경 없이 실패한다. 관리자 편집을 덮어쓰거나 비공개 콘텐츠를 다시 공개하지 않는다. 병음 등 추가 컬럼도 수정하지 않는다. 도구는 최초 등록용이며 기존 본문을 수정하는 동기화 도구가 아니다.

DB 환경이 준비된 실행 환경의 명령은 다음과 같다. 실제 자격증명은 명령·문서에 적지 않는다.

```sh
python api/import_daehak.py --content api/content/daehak.json
python api/import_daehak.py --content api/content/daehak.json --apply
```

이미 실행 중인 서버에는 두 파일만 별도 콘텐츠 디렉터리에 전달하고, FastAPI 컨테이너의 임시 경로로 복사해 기존 `/app`의 DB 연결 코드를 사용한다. 데이터 등록만을 위해 이미지를 바꾸거나 컨테이너를 재시작하지 않는다. 서버의 카탈로그 백업을 먼저 확보하며 실제 `.env`·DB 백업은 로컬로 복사하지 않는다.

## 한자 제목과 병음

2026-09-30 후속 요청으로 작품 `大學 / dà xué`, 11개 장의 한자·병음 제목, 34개 한입의 성조 병음을 추가했다. 본문 한자 1,887자에 음절을 하나씩 대응시키고 구두점·문단을 유지했다. 원문·한국어 제목·번역·해설·순서·공개 상태는 기존 값 그대로다. 장 제목은 기존 한국어 목차에 대응하는 편집 제목이다.

[pypinyin 0.55.0](https://pypi.org/project/pypinyin/0.55.0/)을 일회성 초안 작성에 사용한 뒤 원전 주석과 사전의 문맥별 독음을 대조했다. 앱·서버의 실행 의존성으로 추가하지 않았다. 현대 보통화 성조 부호를 쓰고, `一 yī`·`不 bù` 및 3성 연속은 원음 성조로 통일한다. 고대 중국어 복원음이나 송대 낭독음을 재현하는 자료는 아니다. 어휘 단위 정식 분철 대신 한자별 음절을 띄어 학습용 원문과 대조할 수 있게 했다.

| 문맥 | 적용한 독음 |
| --- | --- |
| 大甲, 於戲 | tài jiǎ, wū hū |
| 緡蠻, 淇澳 | mián mán, qí yù |
| 惡惡臭, 好好色 | wù è chòu, hào hǎo sè |
| 自謙, 心廣體胖 | zì qiè, xīn guǎng tǐ pán |
| 弟者 / 兄弟 | tì zhě / xiōng dì |
| 絜矩, 迸諸四夷 | xié jǔ, bǐng zhū sì yí |
| 儀監于殷, 退而不能遠 | yí jiàn yú yīn, tuì ér bù néng yuàn |

`親民 qīn mín`·`身 shēn`·`命 mìng`은 주석의 교정 글자로 몰래 바꾸지 않았다. 지역·전통 낭독에 이견이 있는 부분은 이번 편집 기준을 명시한다. `菉 lù`, `自謙 qiè`, `好樂 hào lè`, `厭然 yàn rán`을 택했으며 각각 lǜ·qiàn·hào yào·yǎn rán 등 다른 독법을 모두 오류로 단정하지 않는다. `迸 bǐng`은 [교육부 이체자 자전의 해당 대학 용례](https://dict.variants.moe.edu.tw/dictView.jsp?ID=72881&la=0), `遠 yuàn`은 [현대 사전의 피하다 독음](https://zdic.net/hans/远)과 원전 주석을 참고했다. 전문 감수 전 초안이며 운영 작품의 `review_status=draft`를 유지한다.

[`api/fill_daehak_pinyin.py`](../api/fill_daehak_pinyin.py)는 **한자·병음 확장 스키마가 이미 있는 환경**에서 사용한다. 최초 병음 등록 당시 API `1.3.0` 브랜치와 한자·병음 API 소스는 별개였으며, 2026-10-01 학습 확장에서 기존 `1.4.0` 소스를 함께 통합했다. 도구가 스키마를 만들거나 API를 배포하지 않으며 필요한 컬럼이 없으면 거부한다. 최초 본문 등록 도구도 계속 병음을 수정하지 않는다.

```sh
python api/fill_daehak_pinyin.py --content api/content/daehak.json
python api/fill_daehak_pinyin.py --content api/content/daehak.json --apply
```

기본 실행은 계획만 반환한다. `--apply`는 기존 부모·전체 장/한입 ID·원문을 잠금 조회한 뒤 빈 한자 제목·병음 제목·본문 병음만 원자적으로 채운다. 같은 병음은 무변경, 다른 기존 읽기 값이나 원문·계층 충돌은 전체 중단한다. 비어 있는 판본·출처 URL·병음 작성 출처도 채우지만 이미 작성된 출처와 검수 상태는 보존한다. 한국어 제목·번역·해설·정렬·공개 상태를 수정하지 않는다. 등록에는 이 도구와 `import_daehak.py`, 콘텐츠 JSON이 필요하며 서버의 비공개 백업을 먼저 확보한다.

## 검증

기존 Python 3.13 가상환경에서 실행한다. MySQL 검사는 독립된 임시 `mysql:8.4` 컨테이너를 사용하고 제거하며 운영 DB·환경 파일·볼륨은 사용하지 않는다.

```sh
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python scripts/check-daehak-import.py
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python scripts/check-daehak-pinyin.py
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python scripts/check-catalog.py
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python scripts/check-catalog-mysql.py
git diff --check
```

등록 검사에는 계획 확인의 무변경, 완본 저장과 재실행, 공개 API 정렬·준비 상태·본문, 기존 편집·비공개·다른 목차·부분 등록·UUID 충돌 보존, 부모 검증, 실제 중간 INSERT 실패 시 전체 롤백, 병음 보존, 잘못된 파일 거부가 포함된다. 콘텐츠 파일 전체의 등록과 재조회도 검사한다.

병음 검사 11개는 실제 34한입 저장, 부분 보완·동일 값 재실행, 원문·부모·병음 충돌 거부, 기존 출처·검수 상태·편집 보존, 동시 원문 수정 보호·두 등록의 직렬화, 중간 SQL 실패 롤백, 스키마 누락 거부를 확인한다. 테스트 내부에서만 확장 컬럼을 준비하며 다른 worktree나 운영 마이그레이션에 의존하지 않는다. 2026-09-30 병음 등록·기존 본문 등록·카탈로그 API·카탈로그 MySQL 검사 총 39개를 통과했다.

사용자 확인 동선은 iOS의 서재 → 사서오경 → 대학 → 장 → 한입이다. 이미 대학 화면이 열려 있다면 나갔다가 다시 들어가거나 새로고침해 목록을 재조회한다. 자동 API 검증과 실제 기기 화면·전문가 감수·사용자 테스트 승인은 구분한다.

## 초보자 학습 원고 · 2026-10-01 소스 변경

기존 11장·34한입 원고는 그대로 보관하고 [`api/content/daehak-learning.json`](../api/content/daehak-learning.json)에 **70개 학습 단위**의 질문·단어 뜻·쉬운 풀이·핵심·생활 예시·확인 문제를 별도로 작성했다. 기존 한입을 지우거나 새 ID로 교체하지 않는다. 원고를 합치며 한자 1,887자와 병음 전체의 순서·학습 단위별 글자 대응, 단어의 원문 출현과 확인 문제 정답 범위를 대조했다. 기존 번역·해설·전 5장 주희 보전 구분을 보존한다. 학습용 풀이와 예시는 전문 감수 전 자체 작성 초안이며 현대 예시를 원전의 일화로 설명하지 않는다.

| 목차 | 학습 단위 수 |
| --- | --- |
| 경 1장 · 대학의 길 | 12 |
| 전 1장 · 명명덕 | 2 |
| 전 2장 · 신민 | 3 |
| 전 3장 · 지어지선 | 6 |
| 전 4장 · 본말 | 1 |
| 전 5장 · 격물치지 | 5 |
| 전 6장 · 성의 | 6 |
| 전 7장 · 정심수신 | 2 |
| 전 8장 · 수신제가 | 3 |
| 전 9장 · 제가치국 | 8 |
| 전 10장 · 치국평천하 | 22 |

앱은 장 안의 학습 단위를 순서대로 한입·두입으로 표시한다. 첫 원문은 명명덕, 친민의 주희 해석, 지어지선, 지지에서 득에 이르는 순서, 본말의 다섯 단위로 나눴다. 병음은 기존 한자별 음절을 그대로 사용하며 iOS에서는 한자 위에만 표시한다. 소스 작성 시점에는 운영 원고 등록과 사용자 화면 확인을 수행하지 않았으며, 이후 운영 등록은 아래 기록을 따른다.

외피는 `{"version":1,"work_id":"<기존 대학 UUID>","bites":[{"chapter_key":"gyeong-1","bite_key":"gyeong-1-01","learning":{...}}]}`다. `learning` 계약은 [서재 API 문서](catalog-api.md#초보자-학습-자료-learning--소스-150)를 따른다. 기존 원고의 모든 한입 key를 정확히 한 번 포함한다. stable UUID는 기존 등록 함수로 구하며 원고 안의 제목으로 DB 항목을 선택하지 않는다.

[`api/import_daehak_learning.py`](../api/import_daehak_learning.py)는 기본적으로 등록 계획만 반환한다. 필요한 `pinyin`·`learning` 컬럼이 없으면 중단하며 스키마를 자동 변경하지 않는다. 먼저 기존 원고와 학습 단위의 원문·성조 병음을 비교하고, DB의 부모·전체 장·한입 ID와 원문·병음도 잠금 조회로 대조한다. 모든 행을 확인한 뒤 SQL NULL인 learning만 한 트랜잭션으로 채운다. 같은 학습 자료는 `unchanged`, 다른 기존 학습 자료나 편집된 원문·병음·계층이 있으면 전체 중단한다. 제목·번역·해설·출처·검수 상태·정렬·공개 상태는 변경하지 않는다. 부분적으로 등록된 동일 학습 자료는 보존하고 나머지만 채운다.

DB 연결 환경과 추가 스키마가 준비된 환경에서의 사용법이다. 아래 명령의 운영 실행·원고 공개는 이번 소스 작업에 포함하지 않았다.

```sh
python api/import_daehak_learning.py
python api/import_daehak_learning.py --apply
```

필요하면 `--content <학습 원고>`·`--source-content <기존 대학 원고>`를 지정한다. 운영 적용 전에는 서버 내부 비공개 카탈로그 백업과 기존 서비스 보존 절차가 필요하다. DB·환경 파일을 로컬에 복제하지 않는다. 이 도구를 자동 설치·마이그레이션·서버 시작에 연결하지 않는다.

회귀 검사 소스 `scripts/check-daehak-learning.py`는 원고 완전성·입력 제한·병음 대응·실제 임시 MySQL의 무변경 계획·재실행·기존 편집 보존·중간 SQL 실패 롤백·동시 원문 편집·동시 등록 직렬화를 다룬다. 기존 API 검사에는 응답과 학습 필드 생략/명시적 null을 추가했다. 기존 본문/병음 검사 fixture는 이제 통합된 실제 읽기 마이그레이션을 사용한다. 이번 의존 병합의 실제 충돌은 README·AGENTS 문서에만 발생하여 내용·링크·공백을 검토했으며 테스트·검증용 빌드는 실행하지 않았다. 테스트 소스 추가를 통과 결과로 기록하지 않는다.
